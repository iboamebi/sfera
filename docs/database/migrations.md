# Миграции базы данных

**Версия:** 1.1
**Дата актуализации:** 2026-07-16

---

# 1. Назначение

Документ описывает правила работы с изменениями структуры базы данных проекта «Сфера».

---

# 2. Инструмент

Для управления схемой базы данных используется:

```text
Alembic
```

Alembic является единственным способом изменения структуры PostgreSQL.

---

# 3. Основные правила

Запрещается:

- изменять таблицы вручную в PostgreSQL;
- удалять применённые миграции;
- менять историю миграций после публикации.

---

# 4. Жизненный цикл изменения

Каждое изменение выполняется в порядке:

```text
Изменение ORM Model

↓

Создание миграции

↓

Проверка миграции

↓

Применение

↓

Commit в Git
```

---

# 5. Создание миграции

Автоматическая генерация:

```bash
alembic revision --autogenerate -m "description"
```

Проверить созданный файл перед применением.

---

# 6. Применение миграций

Применить все миграции:

```bash
alembic upgrade head
```

---

# 7. Проверка состояния

Текущая версия:

```bash
alembic current
```

История:

```bash
alembic history
```

---

# 8. Новая база данных

Для развёртывания с нуля:

```bash
createdb sphere

alembic upgrade head
```

После выполнения должна быть создана полная схема проекта.

---

# 9. Откат миграций

Используется только в процессе разработки.

Один шаг назад:

```bash
alembic downgrade -1
```

---

# 10. Структура каталога

```text
alembic/

├── env.py

├── script.py.mako

└── versions/

    └── migration_files
```

---

# 11. Правила именования

Имя миграции должно отражать изменение.

Примеры:

```text
add_order_status

create_verification_table

add_arshin_export_fields
```

---

# 12. Проверка на чистой базе

Перед крупными изменениями необходимо проверить:

```text
Создание пустой БД

↓

alembic upgrade head

↓

Запуск приложения

↓

Проверка API
```

---

# 13. Связь с Git

Миграция является частью изменения кода.

Commit должен включать:

- ORM изменения;
- Alembic migration;
- связанные тесты.

---

# 14. Текущая базовая миграция

После пересборки базы актуальная схема создаётся миграцией:

```text
0a49d7113497_initial_schema.py
```

---

# 15. Главный принцип

История базы данных является частью исходного кода проекта и должна быть воспроизводимой на любой новой установке.
