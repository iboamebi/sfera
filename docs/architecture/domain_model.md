# Доменная модель

Версия: 1.1

---

# Основные агрегаты

Система построена по принципам Domain-Driven Design (DDD).

Каждый агрегат имеет собственного Aggregate Root.

---

# Organization

Назначение:

Хранение информации об организациях.

Связанные сущности:

- Customer
- User

---

# Customer

Назначение:

Заказчик услуг.

Связанные агрегаты:

- Order

---

# Order

Главный производственный агрегат.

Содержит:

- номер заказа;
- заказчика;
- статус;
- даты;
- комментарии.

Состав агрегата:

```
Order
    └── OrderItem
```

Order отвечает за жизненный цикл заказа.

---

# OrderItem

Представляет отдельную позицию заказа.

Связанные сущности:

- Instrument
- Verification
- Diagnostic
- Repair

---

# Instrument

Средство измерения.

Связанные сущности:

- InstrumentType
- InstrumentLabel

---

# Verification

Результат поверки.

Содержит:

- методику;
- результат;
- срок действия;
- настройки выгрузки в Аршин.

Связанные сущности:

- Methodology
- ArshinExport

---

# Diagnostic

Результат диагностики.

Может выполняться неоднократно.

Хранится история диагностик.

---

# Repair

Информация о ремонте.

Хранит:

- статус;
- описание;
- использованные материалы.

---

# Material

Материал или комплектующая.

Используется складом и ремонтом.

---

# Warehouse

Склад.

Содержит:

- остатки;
- движения материалов.

---

# PriceList

Прайс-лист.

Содержит:

- множество услуг.

---

# PriceListItem

Позиция прайс-листа.

Используется при расчёте стоимости заказа.

---

# User

Пользователь системы.

Имеет:

- роли;
- права.

---

# Role

Роль пользователя.

---

# Permission

Разрешение.

Используется системой RBAC.

---

# Document

Документ заказа.

---

# DocumentTemplate

Шаблон документа.

---

# AuditLog

Журнал действий пользователей.

---

# ArshinExport

История выгрузки результатов поверки.

---

```

    ▼

    │
    ▼

    │
    ▼

    ├──────────────┐
    │              │
    ▼              ▼

    │               │
    ▼               ▼

                    │
                    ▼
             ArshinExport

            ▼
        Material

PriceList
    │
    ▼

    │
    ▼

    │
    ▼

```

---

# Правила

- Один заказ содержит несколько позиций.
- Каждая позиция относится только к одному заказу.
- Каждая поверка относится к одной позиции заказа.
- Каждая диагностика относится к одной позиции заказа.
- Каждый ремонт относится к одной позиции заказа.
- Один прибор может встречаться в разных заказах.
- Методика поверки хранится отдельно и переиспользуется.
- История выгрузок в Аршин никогда не удаляется.
