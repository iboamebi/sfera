# Заказчики

```
Customer
```

Хранит контактных лиц организации.

Связи:

```
Customer
    └── Order
```

---

# Заказы

```
Order
```

Главная производственная сущность.

Содержит:

- заказчика;
- позиции;
- статусы;
- производственную историю.

---

# Позиции заказа

```
OrderItem
```

Каждая позиция соответствует одному средству измерения.

Через неё выполняются все работы.

---

# Средство измерения

```
Instrument
```

Содержит постоянные сведения о приборе.

Связано с:

- типом;
- маркировками;
- историей заказов.

---

# Тип средства измерения

```
InstrumentType
```

Справочник типов.

---

# Маркировка

```
InstrumentLabel
```

Позволяет хранить:

- QR;
- Barcode;
- DataMatrix.

История сохраняется.

---

# Диагностика

```
Diagnostic
```

История диагностик.

Допускается несколько диагностик на одну позицию заказа.

---

# Ремонт

```
Repair
```

История ремонтов.

Содержит:

- статус;
- описание;
- рекомендации.

---

# Поверка

```
Verification
```

Основной производственный результат.

Содержит:

- дату;
- результат;
- методику;
- срок действия;
- признак экспорта.

---

# Методика

```
Methodology
```

Справочник методик поверки.

Используется через внешний ключ.

---

# Экспорт Аршин

```
ArshinExport
```

История всех экспортов.

Не изменяет результаты поверки.

---

# Производственные перемещения

```
ProductionMovement
```

Фиксирует прохождение заказа по производственным этапам.

---

# Склад

```
Warehouse
```

Справочник складов.

---

# Материал

Material

---

- поступлений;

# Аудит

```
AuditLog
```

История изменения данных.

---

# Бизнес-правила

1. Заказ является корнем агрегата.

2. Все работы выполняются только через OrderItem.

3. История операций не удаляется.

4. Поверка невозможна без позиции заказа.

5. Экспорт в Аршин возможен только для завершённой поверки.

6. Списание материалов фиксируется через WarehouseMovement.

7. Любое изменение важных данных должно отражаться в AuditLog.
