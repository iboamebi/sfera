# Testing Standard

## Проект

Сфера

## Версия

1.0

## Статус

Утверждено

---

# Назначение

Настоящий документ определяет единый стандарт тестирования проекта «Сфера».

Все новые модули сопровождаются тестами.

Код без тестов считается незавершенным.

---

# Цели тестирования

Тестирование должно обеспечивать:

- корректность бизнес-логики;
- стабильность системы;
- безопасность рефакторинга;
- раннее обнаружение ошибок;
- воспроизводимость результатов.

---

# Уровни тестирования

Используются четыре уровня.

```text
API Tests

↓

Application Tests

↓

Domain Tests

↓

Infrastructure Tests
```

---

# Структура каталога

```text
tests/

├── api/
│
├── application/
│
├── domain/
│
├── infrastructure/
│
├── fixtures/
│
├── factories/
│
└── conftest.py
```

---

# Unit Tests

Проверяют только один класс или функцию.

Не используют:

- PostgreSQL;
- HTTP;
- SQLAlchemy;
- внешние сервисы.

Пример:

```text
Customer

Order

Repair

Verification
```

---

# Domain Tests

Проверяют:

- инварианты;
- правила;
- Value Objects;
- Domain Events;
- исключения.

Domain тестируется полностью изолированно.

---

# Application Tests

Проверяют:

- пользовательские сценарии;
- Service;
- Unit of Work;
- взаимодействие Repository.

Repository может быть заменен mock-объектом.

---

# Infrastructure Tests

Проверяют:

- Repository;
- SQLAlchemy;
- PostgreSQL;
- миграции;
- транзакции;
- файловое хранилище.

Используется тестовая база данных.

---

# API Tests

Проверяют:

- HTTP-коды;
- маршруты;
- сериализацию;
- DTO;
- обработку ошибок;
- Swagger.

Используется TestClient.

---

# Наименование тестов

Файл:

```text
test_customer_service.py

test_order_repository.py
```

Функция:

```python
test_create_customer()

test_close_order()

test_archive_material()
```

---

# Правило одного сценария

Один тест проверяет одну ситуацию.

Плохо:

```python
test_customer()
```

Хорошо:

```python
test_create_customer()

test_archive_customer()

test_restore_customer()
```

---

# Структура теста

Используется схема:

```text
Arrange

Act

Assert
```

Пример:

```python
# Arrange

# Act

# Assert
```

---

# Использование Mock

Mock применяется только для внешних зависимостей.

Например:

- SMTP;
- Telegram;
- ФГИС Аршин;
- файловое хранилище;
- внешние REST API.

Бизнес-логику не заменяют mock-объектами.

---

# Фикстуры

Общие данные выносятся в fixtures.

Пример:

```text
customer_factory

order_factory

warehouse_factory
```

---

# Тестовые данные

Каждый тест создает собственные данные.

Тесты не должны зависеть друг от друга.

---

# Независимость

Тест можно запускать отдельно.

Порядок выполнения не должен влиять на результат.

---

# Повторяемость

Повторный запуск должен давать одинаковый результат.

---

# Покрытие

Минимальное покрытие:

```text
Domain

100%
```

```text
Application

90%
```

```text
Infrastructure

80%
```

```text
API

80%
```

---

# Что обязательно тестировать

Для каждой новой сущности:

- создание;
- изменение;
- архивирование;
- ошибки;
- исключения;
- граничные условия.

---

# Что запрещено

Не тестируются:

- сторонние библиотеки;
- SQLAlchemy;
- FastAPI;
- Python.

Тестируется только собственный код проекта.

---

# Скорость

Unit Tests должны выполняться быстро.

Интеграционные тесты допускают более длительное выполнение.

---

# CI

Перед объединением изменений автоматически выполняются:

- форматирование;
- линтер;
- типизация;
- unit-тесты;
- integration-тесты.

При наличии ошибок объединение запрещено.

---

# Контроль качества

Перед коммитом необходимо убедиться:

- новые функции покрыты тестами;
- существующие тесты проходят успешно;
- отсутствуют пропущенные сценарии;
- тесты независимы друг от друга.

---

# Итог

Тестирование является обязательной частью разработки проекта «Сфера».

Каждый новый модуль должен сопровождаться достаточным набором тестов, подтверждающих корректность его работы и соответствие архитектурным требованиям.
