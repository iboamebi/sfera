# Стратегия тестирования

**Версия:** 1.1
**Дата актуализации:** 2026-07-16

---

# 1. Назначение

Документ определяет правила тестирования проекта «Сфера».

Цель тестирования:

- защита бизнес-правил;
- предотвращение регрессий;
- контроль качества изменений;
- подтверждение стабильности системы.

---

# 2. Принципы тестирования

Основные принципы:

- тестировать бизнес-логику независимо от технологий;
- проверять критические сценарии;
- не использовать рабочую базу данных;
- каждый тест должен иметь одну ответственность.

---

# 3. Уровни тестирования

Используется структура:

```text
End-to-End Tests

        ▲

Integration Tests

        ▲

Unit Tests
```

---

# 4. Unit Tests

## Назначение

Проверка отдельных компонентов без внешних зависимостей.

---

## Проверяются

- Domain Entities;
- Value Objects;
- Domain Services;
- бизнес-правила.

---

## Особенности

Unit-тесты:

- не используют PostgreSQL;
- не запускают FastAPI;
- не используют реальные внешние сервисы.

---

## Примеры

Проверка:

```text
Verification

SUITABLE

UNSUITABLE
```

Проверка:

```text
Order Status Transition
```

---

# 5. Integration Tests

## Назначение

Проверка взаимодействия компонентов системы.

---

## Проверяются

- Repository;
- SQLAlchemy;
- PostgreSQL;
- Unit Of Work;
- Application Services.

---

# 6. API Tests

## Назначение

Проверка REST API.

---

## Проверяются

- HTTP методы;
- статус-коды;
- валидация;
- сериализация;
- права доступа.

---

# 7. End-to-End Tests

## Назначение

Проверка полного пользовательского сценария.

---

## Основные сценарии

### Поверка средства измерений

```text
Создание заказа

↓

Регистрация СИ

↓

Проведение поверки

↓

Формирование результата

↓

Экспорт в Аршин
```

---

### Ремонт

```text
Приём прибора

↓

Диагностика

↓

Ремонт

↓

Списание материалов

↓

Выдача
```

---

# 8. Структура тестов

```text
tests/

├── unit/

│   ├── domain/
│   └── application/


├── integration/

│   ├── repositories/
│   └── database/


└── api/

    └── routers/
```

---

# 9. Именование тестов

Формат:

```text
test_<объект>_<условие>_<результат>
```

Пример:

```text
test_verification_unsuitable_requires_reason
```

---

# 10. Приоритет покрытия

Порядок важности:

1. Domain правила.
2. Application сценарии.
3. Репозитории.
4. API.
5. Внешние интеграции.

---

# 11. Запуск тестов

Основная команда:

```bash
pytest
```

С покрытием:

```bash
pytest --cov=app
```

---

# 12. Запрещается

Не допускается:

- тестировать всю бизнес-логику только через API;
- использовать рабочую базу;
- создавать зависимые друг от друга тесты;
- отключать тесты без причины.

---

# 13. Главный принцип

Критические бизнес-правила защищаются быстрыми Unit-тестами.

Взаимодействие компонентов подтверждается Integration и API тестами.
