# Правила проектирования базы данных

Версия: 1.1

---

# Общие положения

База данных:

- PostgreSQL
- SQLAlchemy 2.0 ORM
- Alembic

Все изменения структуры выполняются только через миграции Alembic.

---

# Первичные ключи

Все таблицы используют UUID.

```
id UUID PRIMARY KEY
```

---

# Базовая модель

Все таблицы наследуются от BaseModel.

Обязательные поля:

```
id
created_at
updated_at
archived
```

---

# Внешние ключи

Все связи оформляются через ForeignKey.

Пример

```
customer_id
order_id
instrument_id
```

---

# Индексы

Индекс обязателен для:

- всех внешних ключей;
- UUID поиска;
- полей статусов;
- номеров документов;
- серийных номеров;
- кодов справочников.

---

# Уникальные ограничения

Используются только там, где это действительно необходимо.

Например

```
orders.number

roles.name

permissions.code

methodologies.code
```

---

# Enum

Все перечисления оформляются через Python Enum.

В PostgreSQL используются именованные ENUM.

---

# Nullable

Поле должно быть nullable только при наличии бизнес-основания.

По умолчанию используется:

```
nullable=False
```

---

# Удаление

Физическое удаление данных запрещено.

Используется логическое удаление.

```
archived = True
```

---

# История

История операций не удаляется.

Это относится к:

- Verification;
- Diagnostic;
- Repair;
- ArshinExport;
- AuditLog;
- WarehouseMovement.

---

# Денежные значения

Используется

```
Numeric
```

Использование Float запрещено для денежных сумм.

---

# Количество материалов

Используется

```
Numeric(12,3)
```

---

# Даты

Дата без времени

```
Date
```

Дата со временем

```
DateTime(timezone=True)
```

---

# Связи

Используется

```
relationship()

back_populates
```

Использование backref запрещено.

---

# Каскадное удаление

Используется только при владении сущностью.

Например

```
Order
    └── OrderItem

OrderItem
    ├── Verification
    ├── Diagnostic
    └── Repair
```

Используется

```
cascade="all, delete-orphan"
```

---

# Наименование таблиц

Используются множественные имена.

```
orders
customers
materials
warehouses
```

---

# Наименование полей

Используется snake_case.

Пример

```
verification_date

planned_issue_at

customer_inventory_number
```

---

# Миграции

Каждое изменение модели сопровождается новой миграцией.

Редактирование уже применённых миграций запрещено.

---

# Автогенерация

Разрешается использовать

```
alembic revision --autogenerate
```

После генерации миграция обязательно проверяется вручную.

---

# Резервное копирование

Перед изменением структуры рабочей базы рекомендуется создавать резервную копию.

---

# Основной принцип

Структура базы данных должна:

- отражать предметную область;
- поддерживать DDD;
- обеспечивать целостность данных;
- быть расширяемой без нарушения существующей модели.
