# Регламент разработки

Версия: 1.1

---

# Основная ветка

Работа ведётся в ветке

```
develop
```

Ветка `main` используется только для стабильных релизов.

---

# Порядок разработки

Каждая новая функциональность проходит одинаковые этапы.

```
Анализ

↓

Проектирование

↓

Изменение Domain

↓

Изменение Models

↓

Миграция Alembic

↓

Repository

↓

Service

↓

API

↓

Тестирование

↓

Документация

↓

Commit
```

---

# Перед началом работы

Перед разработкой необходимо:

- изучить Domain Map;
- проверить Конституцию проекта;
- определить затрагиваемые агрегаты;
- определить необходимые миграции.

---

# Добавление новой сущности

Последовательность:

1. Domain Entity
2. SQLAlchemy Model
3. Alembic Migration
4. Repository
5. Service
6. Pydantic Schema
7. Router
8. Tests
9. Документация

---

# Изменение модели

Любое изменение модели сопровождается:

- обновлением ORM;
- новой миграцией Alembic;
- обновлением документации.

Редактирование применённых миграций запрещено.

---

# Бизнес-логика

Новая бизнес-логика реализуется только в:

```
app/application/
```

или

```
app/domains/
```

---

# Router

Router не содержит:

- SQL;
- бизнес-логики;
- вычислений.

Router только принимает запрос и вызывает сервис.

---

# Repository

Repository отвечает исключительно за работу с хранилищем данных.

---

# Service

Service реализует:

- сценарии работы;
- проверки;
- вызовы репозиториев;
- управление транзакциями.

---

# Domain

Domain содержит:

- сущности;
- события;
- Value Objects;
- фабрики;
- интерфейсы репозиториев.

---

# Документация

После завершения каждой логически законченной задачи обновляются:

- архитектурная документация;
- описание модулей;
- диаграммы (при необходимости).

---

# Коммиты

Один коммит — одна законченная логическая задача.

Примеры:

```
feat(order): add order service

feat(verification): add methodology relation

fix(api): correct repository injection

docs: update domain map
```

---

# Проверка перед коммитом

Перед коммитом необходимо убедиться, что:

- проект запускается;
- миграции выполняются;
- Swagger открывается;
- отсутствуют ошибки импорта;
- документация актуальна.

---

# Перед Push

Выполнить:

```bash
git status
```

```bash
alembic upgrade head
```

```bash
uvicorn app.main:app --reload
```

Проверить основные маршруты через Swagger.

---

# Работа с миграциями

Создание:

```bash
alembic revision --autogenerate -m "description"
```

Применение:

```bash
alembic upgrade head
```

---

# Работа с документацией

Все документы проекта хранятся в каталоге:

```
docs/
```

Документация обновляется одновременно с изменением кода.

---

# Основной принцип

Каждое изменение должно:

- соответствовать Конституции проекта;
- сохранять архитектурные границы;
- сопровождаться миграцией (при изменении БД);
- сопровождаться обновлением документации;
- быть завершённым и работоспособным перед коммитом.
