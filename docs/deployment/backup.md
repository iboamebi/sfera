# Резервное копирование проекта «Сфера»

**Версия:** 1.1
**Дата актуализации:** 2026-07-16

---

# 1. Назначение

Документ описывает правила резервного копирования данных и компонентов системы «Сфера».

Цель:

- защита от потери данных;
- возможность восстановления системы;
- сохранение истории работы.

---

# 2. Объекты резервирования

Резервному копированию подлежат:

```text
PostgreSQL Database

Исходный код

Документы

Конфигурация

Миграции
```

---

# 3. База данных

Основной объект:

```text
sphere
```

Используется резервное копирование PostgreSQL.

Пример:

```bash
pg_dump sphere > sphere_backup.sql
```

---

# 4. Восстановление базы

Восстановление:

```bash
psql sphere < sphere_backup.sql
```

После восстановления:

```bash
alembic upgrade head
```

---

# 5. Исходный код

Код хранится:

```text
GitHub Repository
```

Основная ветка разработки:

```text
develop
```

Резервная копия:

- Git history;
- миграции;
- документация.

---

# 6. Документы

Файлы документов не должны храниться только в базе данных.

Резервируются:

```text
Storage
```

Содержимое:

- акты;
- отчёты;
- сертификаты;
- экспортные файлы.

---

# 7. Конфигурация

Резервируются:

```text
.env.example

configuration files

deployment scripts
```

Файлы с секретами:

```text
.env
```

хранятся отдельно и защищённо.

---

# 8. Периодичность

Рекомендуемый порядок:

## Ежедневно

```text
Database Backup
```

---

## Еженедельно

```text
Full Backup
```

Включает:

- базу;
- документы;
- конфигурацию.

---

# 9. Проверка резервных копий

Резервная копия считается рабочей только после проверки восстановления.

Проверка:

```text
Создать тестовое окружение

↓

Восстановить данные

↓

Запустить приложение

↓

Проверить API
```

---

# 10. Хранение копий

Копии должны храниться отдельно от рабочего сервера.

Возможные варианты:

- внешний сервер;
- сетевое хранилище;
- защищённое облачное хранилище.

---

# 11. Аварийное восстановление

Порядок восстановления:

```text
Установить окружение

↓

Восстановить PostgreSQL

↓

Применить миграции

↓

Развернуть приложение

↓

Проверить работу
```

---

# 12. Главный принцип

Резервное копирование должно обеспечивать восстановление полной работоспособности системы «Сфера», а не только отдельных файлов.
