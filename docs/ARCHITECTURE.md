# Sfera Architecture

## Общие принципы

Проект развивается по архитектуре:

DDD + Clean Architecture

Главный принцип:

Бизнес-правила не должны зависеть от инфраструктуры.


---

# Слои приложения

## Domain

Содержит:

- бизнес-сущности;
- value objects;
- доменные правила;
- интерфейсы репозиториев.

Не зависит от:

- FastAPI;
- SQLAlchemy;
- PostgreSQL.


---

## Application

Содержит:

- application services;
- use cases;
- сценарии работы системы.

Отвечает за:

- координацию действий;
- выполнение бизнес-сценариев;
- взаимодействие с репозиториями.


---

## Infrastructure

Содержит:

- SQLAlchemy repositories;
- работу с БД;
- внешние интеграции;
- файловое хранилище.

Реализует интерфейсы Domain.


---

## API

Содержит:

- FastAPI routers;
- схемы запросов/ответов;
- dependency injection.

API не содержит бизнес-логики.


---

# Основные сущности

## Order

Центральная бизнес-сущность системы.

Назначение:

- заказ клиента;
- объединение производственных операций;
- контроль жизненного цикла.


Workflow:

Order

↓

Case

↓

Workflow

↓

Technological Card

↓

Verification / Repair / Diagnostic


---

OrderStatus:

- COMPLETED

# Миграция Legacy CRUD

Текущий legacy:

API

↓

CRUD

↓

Model


Целевой вариант:

API

↓

Service

↓

Repository

↓

Infrastructure


CRUD удаляется только после:

- переноса логики;
- проверки работы;
- успешного тестирования.


---

# Принципы изменений

При разработке:

- один файл за один шаг;
- минимальные изменения;
- сохранение работоспособности;
- анализ существующего кода перед изменением;
- отсутствие предположений о структуре проекта.


---

# Интеграции

- XLSM экспорт;
- документы;
- склад;
- финансы.


---

# Тестирование

Каждая миграция должна сопровождаться проверкой:

- существующих тестов;
- API;
- миграций БД;
- основных сценариев.
