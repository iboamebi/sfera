# Модуль Diagnostic

**Версия:** 1.1
**Дата актуализации:** 2026-07-16

---

# 1. Назначение

Diagnostic реализует процесс диагностики средств измерений в системе «Сфера».

Модуль используется для определения:

- технического состояния прибора;
- причины неисправности;
- необходимости ремонта;
- дальнейшего производственного маршрута.

---

# 2. Место в бизнес-процессе

Диагностика выполняется в рамках заказа:

```text
Customer

↓

Order

↓

OrderItem

↓

Diagnostic

↓

Repair / Verification
```

---

# 3. Основная сущность

```text
Diagnostic
```

Diagnostic является результатом технического обследования средства измерения.

---

# 4. Основные данные

Хранятся:

- дата диагностики;
- исполнитель;
- описание неисправности;
- выявленные проблемы;
- рекомендации;
- результат диагностики.

---

# 5. Версионирование диагностики

Диагностика является версионируемой.

Один OrderItem может иметь несколько диагностик:

```text
OrderItem

↓

Diagnostic v1

↓

Diagnostic v2

↓

Diagnostic v3
```

Используется актуальная версия.

---

# 6. Статусы диагностики

Пример:

```text
CREATED

↓

IN_PROGRESS

↓

COMPLETED
```

---

# 7. Результаты диагностики

Возможные результаты:

```text
NO_FAULT_FOUND

REPAIR_REQUIRED

VERIFICATION_REQUIRED

UNSUITABLE
```

---

# 8. Связь с ремонтом

Если требуется ремонт:

```text
Diagnostic

↓

Repair
```

Диагностика является основанием для выполнения ремонтных работ.

---

# 9. Связь с поверкой

После диагностики возможно:

```text
Diagnostic

↓

Verification
```

Например:

- прибор исправен;
- требуется только поверка.

---

Основные компоненты:

```text
DiagnosticFactory
```

Основной сервис:

```text
DiagnosticService
```

Операции:

```text

```

---

# 12. Repository

Интерфейс:

```text
DiagnosticRepository
```

Реализация:

```text
SQLAlchemyDiagnosticRepository
```

---

# 13. Ограничения

Запрещается:

- создавать диагностику без OrderItem;
- удалять историю диагностик;
- изменять завершённую диагностику без создания новой версии.

---

# 14. Документы

Результаты диагностики могут использоваться для формирования:

- технического заключения;
- заказ-наряда;
- отчёта ремонта.

---

# 15. Тестирование

Проверяются:

- создание диагностики;
- версионирование;
- выбор актуальной версии;
- связь с ремонтом;
- корректность результатов.

---

# 16. Главный принцип

Diagnostic является точкой принятия технического решения и определяет дальнейший производственный маршрут средства измерения.
