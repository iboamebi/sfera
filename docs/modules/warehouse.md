# Модуль Warehouse

**Статус:** реализован базовый складской учёт материалов, остатков, резервов и журнала движений.

## 1. Назначение

Модуль обеспечивает:
- ведение справочника материалов;
- учёт материалов по складам;
- хранение физического и зарезервированного количества;
- поступление, списание и резервирование материалов;
- просмотр журнала складских движений.

Интеграция списания материалов непосредственно с процессом ремонта в текущей реализации не подтверждена и не описывается как действующая функция.

## 2. Основные сущности

- **Warehouse** — склад.
- **Material** — материал или комплектующая.
- **WarehouseStock** — текущий остаток материала на складе.
- **WarehouseMovement** — запись об операции, изменившей физический остаток или резерв.

Для остатка доступны:
- физическое количество — `quantity`;
- зарезервированное количество — `reserved_quantity`;
- доступное количество — физическое количество минус зарезервированное.

## 3. Типы движений

В Domain и ORM определены следующие значения:

| Тип | Назначение | Изменение остатка |
|---|---|---|
| `RECEIPT` | Поступление | Увеличивает физическое количество |
| `ISSUE` | Списание | Уменьшает физическое количество, не затрагивая резерв |
| `RESERVATION` | Резервирование | Увеличивает зарезервированное количество |
| `RELEASE` | Освобождение резерва | Уменьшает зарезервированное количество |
| `ADJUSTMENT` | Корректировка | Значение присутствует в enum, но операция создания пока отклоняется |

Количество движения передаётся положительным числом. Направление изменения определяется типом движения, а не знаком количества.

Межскладское перемещение (`TRANSFER`), возврат отдельным типом (`RETURN`) и корректировка остатков пока не реализованы.

## 4. Правила изменения остатков

Изменения выполняются через `WarehouseApplicationService`.

Операции изменения остатка и запись соответствующего `WarehouseMovement` выполняются в одной транзакции Unit of Work:
- при успешном выполнении транзакция фиксируется;
- при ошибке транзакция откатывается.

Domain проверяет, что количество положительное, списание не превышает доступный остаток, а освобождение резерва не превышает зарезервированное количество.

Доступ к операциям изменения склада разрешён ролям `ADMIN` и `WAREHOUSE`. Запросы записи защищены CSRF-проверкой.

## 5. Журнал движений

Для склада доступен API чтения журнала с фильтрами:
- склад — обязательный параметр маршрута;
- материал;
- заказ;
- тип движения;
- дата начала и окончания.

Пагинация: по умолчанию 50 записей, максимум 200 за запрос. Сначала возвращаются более новые движения. В выборку не включаются архивированные записи.

В интерфейсе журнала отображаются дата, материал, тип и количество движения, номер заказа и комментарий. Если движение связано с заказом, номер заказа ведёт на его страницу.

## 6. Ограничения текущей реализации

Пока не реализованы:
- межскладское перемещение;
- отдельный тип возврата;
- проведение корректировки (`ADJUSTMENT`);
- автоматическое списание материалов из процесса ремонта;
- автоматическая связь движений с работами по поверке;
- отчёты и инвентаризационные процедуры.

Не следует считать перечисленные функции доступными только на основании наличия соответствующих бизнес-сценариев или значений enum.

## 7. Основные компоненты

- Domain: `Warehouse`, `WarehouseStock`, `WarehouseMovement`, `MovementType`.
- Application: `WarehouseApplicationService`, сервис чтения журнала движений.
- Infrastructure: SQLAlchemy-репозитории остатков и движений.
- API: маршруты складов, остатков и движений.
- Frontend: страница остатков и журнал движений на странице склада.
